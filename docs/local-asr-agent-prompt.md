## 必须满足的圈说接口：quanshuo-asr-v1

圈说使用以下明确的 WebSocket 协议，不是任意 OpenAI、FunASR、Ollama 地址都能直接接入。如果所选引擎协议不同，请部署一个薄适配器，调用该引擎的本地 API/SDK，并转换为下面的协议。适配器与模型都可以独立于圈说运行。

- 默认地址 `ws://127.0.0.1:8765/asr`；端口占用时选择空闲端口并同步圈说配置。只绑定回环地址，不开放公网或局域网。圈说仅允许 localhost、127.0.0.1、[::1] 的 ws/wss 地址，绕过系统代理，不发送云端 API Key。
- 一条 WebSocket 连接对应一次独立录音。所有 JSON 为 UTF-8 文本消息，属性名区分大小写。音频为二进制消息，不是 JSON/base64/WAV。
- 圈说发送开始消息：

```json
{"type":"start","protocol":"quanshuo-asr-v1","model":"default","language":"zh","audio":{"format":"pcm_s16le","sampleRate":16000,"channels":1}}
```

`model` 是服务端可解析的模型或配置 ID；请提供 `default` 或将真实 ID 填入圈说。`language` 可能为 zh/en/ja/ko；不支持时返回明确错误。验证格式及所选模型，不要静默使用另一个配置。

- 模型加载完成、服务可接收音频后回复：

```json
{"type":"ready","protocol":"quanshuo-asr-v1","modelInfo":{"name":"实际加载的模型名称","catalogId":"paraformer-streaming-int8","runtime":"实际运行时及版本","device":"cpu","precision":"INT8","estimatedVramMb":0}}
```

`modelInfo` 让圈说设置直接显示实际模型与资源预算。新建或维护适配器时请提供它：`name` 填实际加载的模型名称，不能回显 `default` 或把推荐候选当成当前模型；`runtime`、`device`、`precision` 填实际信息。`estimatedVramMb` 是预计模型显存，`estimatedRamMb` 是可选的预计系统内存，单位 MB（1024 MB = 1 GB），必须是非负有限数字。只有确实全部在 CPU 上推理才把显存写 0；未知字段省略，不猜测，不把估算叫作实测。不要为填资料临时加载第二个模型或执行额外下载。

界面切换需要 `modelInfo.catalogId`，三个值分别为 `paraformer-streaming-int8`、`qwen3-asr-0.6b`、`qwen3-asr-1.7b`。它必须对应实际加载的模型；上面只是 CPU 示例，Qwen 不得照抄 CPU、INT8 或 0 显存。`name` 必须与登记文件的 `expectedModelName` 逐字相同。旧服务没有 catalogId 仍能通过手动地址识别，但不能冒充已完成界面切换验收。

这是一项向后兼容的可选扩展：旧服务只回 ready 仍能识别，设置会显示“服务已连接，尚未报告模型”。圈说在测试连接后保存带地址、配置 ID 和时间的资料；打开设置只读缓存，不会连接服务或加载模型，也不把缓存当作实时运行状态。更新或切换模型后重新测试连接，确认名称、设备、精度和显存预算都对应实际配置。诊断 JSON 的 `modelInfo` 也应与部署一致。

圈说连接限时 5 秒，连接成功后等待 ready 最长 90 秒。不要在模型尚未准备好时谎报 ready；冷启动超过限制应提前预热模型。圈说在加载期间保存录音，ready 后才发送累计音频。

- 圈说随后发送 16kHz、单声道、16bit little-endian 原始 PCM。实时录音通常每包约 100ms，重转写会连续快速发送；不要假设分包与句子边界一致。支持静音、很短的音频和长录音；暂停时会继续收到静音。
- 返回临时结果与句末确认：

```json
{"type":"transcript","text":"今天的天","isFinal":false}
{"type":"transcript","text":"今天的天气很好。","isFinal":true}
{"type":"transcript","text":"今天的天气很好。我们出门","isFinal":false}
{"type":"transcript","text":"今天的天气很好。我们出门吧。","isFinal":true}
```

**text 始终是这次连接从开头到现在的累计全文，不是增量，也不是单句。** isFinal=true 表示累计全文到这里的句子已确认，不代表整次录音结束。已确认的前缀必须保持逐字不变（包括标点、空格）；只能修订未确认尾部。圈说会拒绝修改已确认前缀的服务。服务内部的分段结果应按段 ID 覆盖并累计，避免重复拼接。用户在圈说中的手动编辑由圈说处理，不要向用户的其他应用发送文字。

- 音频输入结束后圈说发送 `{"type":"finish"}`。必须处理完所有已接收音频，flush 最后一段（即使没有尾部静音），发送最终累计全文 `isFinal:true`，然后回复 `{"type":"finished"}`。收到 finished 前不能把关闭连接当成成功。全程静音可直接回复 finished，也可先回复空的最终全文，不要为静音编造文字。圈说发出 finish 后，实时录音等待 finished 最长 60 秒；此前的模型准备和待发送音频排空另计。文件重转写按录音长度增加此等待时间。
- 错误（显存不足、模型不存在、格式不支持、队列满、推理异常）返回：

```json
{"type":"error","message":"模型显存不足，请使用较轻配置后重新转写。"}
```

错误后停止该会话，不得再返回 finished。错误信息不得包含密钥或整段私人音频/文字。不要发送协议以外的 status、ping 等 JSON；保活用标准 WebSocket ping/pong。单条返回 JSON 不超过 4MiB。
- 客户端断开时取消该会话、回收缓存；不要把上一条连接的文字或音频带入下一条。模型可常驻并复用，但会话状态必须隔离。根据资源决定串行会话或明确返回忙碌错误。
- 推理不要阻塞 WebSocket I/O；设置有界队列和背压。文件重转写可能比实时更快送入音频，不能丢包；如果无法继续，返回 error。圈说发送单包最多等 10 秒，实时待发送队列最多约 100 秒，超过会保留 WAV 并停止实时识别。结束录音后，在模型 ready 之后最多用 60 秒排空待发送音频；超时停止转写并保留录音，不会无限等积压。模拟流式只处理最新待修订窗口，避免每一帧都启动一份重复推理任务。
- 模型和转写始终本地运行，不允许失败时自动调用云端。实际模型无原生流式能力时，由适配器实现有界窗口/VAD/去重；不能等用户按结束才开始整个录音的唯一一次识别并称为边说边出字。

## 验证：不能只测试端口

1. 先按上面的完整顺序验证 ready、PCM 输入、临时结果、当前句修订、下一句累计、finish、finished。再测静音、短句、中英术语、连续多句、停顿、无尾部静音结束、断开重连，以及快速发送完整 WAV。异常不得假装成功。
2. 使用公开许可的语音样本，或用户明确同意的一段测试录音。实时验收用含多句、停顿且足够长的音频，记录文字、首个非空结果等待时间、结束后等待时间、处理速度、峰值显存与系统内存。实测数字附机器和模型版本；无法测量的项目标明未测。分别检查冷启动和预热后表现，并在停止/重新启动本次部署的服务后再连接一次。单次测试不等于长时间稳定性证明。
3. 使用圈说程序自身的诊断入口验收（替换所有尖括号占位符；地址与模型 ID 必须与实际部署一致）。每次使用新的 JSON 路径，缺少输出文件不能拿旧结果当成功：

```powershell
$exe = '<圈说 exe 的绝对路径>'
$wav = '<16kHz单声道PCM16 WAV绝对路径>'
$endpoint = '<实际本机服务地址，例如 ws://127.0.0.1:8765/asr>'
$model = '<实际模型或配置 ID，例如 default>'
$output = Join-Path $env:TEMP ('quanshuo-local-asr-' + [Guid]::NewGuid().ToString('N') + '.json')
$arguments = @('--smoke-local-asr', '--smoke-input', ('"' + $wav + '"'), '--smoke-endpoint', ('"' + $endpoint + '"'), '--smoke-model', ('"' + $model + '"'), '--smoke-output', ('"' + $output + '"'), '--smoke-pacing', '100')
$process = Start-Process -FilePath $exe -ArgumentList $arguments -WindowStyle Hidden -PassThru -Wait
if (-not (Test-Path -LiteralPath $output)) { throw '圈说没有生成本次诊断 JSON，请检查程序版本、路径和参数。' }
$result = Get-Content -LiteralPath $output -Raw -Encoding UTF8 | ConvertFrom-Json
$result | ConvertTo-Json -Depth 5
$process.ExitCode
```

此命令只发送指定 WAV 到指定本机服务，不开麦克风、不改用户设置。检查退出码及本次 JSON；参数错误会以非零码退出并尽量写入指定 JSON。无法写入 JSON 或缺少以下字段都不能算通过。

- `protocolOk`：ready、音频输入、finish、finished 完整完成。`ok` 还要求文字非空；`ok=true` 不代表边说边出字或准确。
- `pacingMode=realtime`（`pacing=100`）时，`streamingObserved` 表示送音频期间、调用 finish 之前是否观察到非空文字；`transcriptsBeforeFinish`、`partialsBeforeFinish` 分别计此期间的非空结果和临时结果。只在 finish 后才收到 partial 的服务不算实时通过。短句/静音可能来不及产生临时结果，不能单独用于证明或否定流式能力。使用多句样本检查临时结果及当前句修订。
- `readyMs` 是从诊断开始到模型 ready 的时间，`audioDurationMs` 是音频长度，`firstTextMs` 包含连接及模型准备，`finishWaitMs` 是调用 finish 到完成/失败的等待，`elapsedMs` 是总时间。`text` 必须人工或按参考文字核对；不能因为文字非空就宣称准确。
- 再把 `--smoke-pacing` 改为 `0`，使用新的输出路径验证快速重转写与背压。此时 `pacingMode=fast`，`streamingObserved=null`，只判断协议完成及转写内容；不能将快速发送结果当作实时延迟测量。其他发送间隔标为 custom，也不作实时验收。

## 登记到圈说，让我在界面切换

安装后的模型可以并存，默认保留我正在使用的识别来源和模型。只登记本次已通过真实验收的目标，不自动切换，不下载另外两个，不改写整份 settings.json 或覆盖其他模型的登记文件。

完成真实模型、停止再启动、资源释放等本次可执行的验收后，再在 `%LOCALAPPDATA%\QuanShuo\local-asr-profiles` 下，为本次模型原子写入一份 UTF-8 JSON。覆盖已存在的目标文件前保存其原始内容；不改其他模型文件。文件名必须是 `<登记ID>.json`；仅有以下三个固定 ID：

| 模型 | 登记 ID / 文件名主体 |
|---|---|
| Paraformer Streaming INT8 | `paraformer-streaming-int8` |
| Qwen3-ASR 0.6B | `qwen3-asr-0.6b` |
| Qwen3-ASR 1.7B | `qwen3-asr-1.7b` |

示例结构（必须替换成已验证的真实值，不是通用可照抄配置）：

```json
{
  "schemaVersion": 1,
  "id": "qwen3-asr-0.6b",
  "endpoint": "ws://127.0.0.1:8765/asr",
  "model": "qwen3-asr-0.6b",
  "expectedModelName": "Qwen/Qwen3-ASR-0.6B"
}
```

`model` 是该服务实际接受的 start.model，`expectedModelName` 是真实 ready.modelInfo.name。两个模型不能共用同一地址和同一 model ID。单模型旧服务可以继续使用 default；同一服务接入多个模型时须提供明确、不同的配置 ID，并在登记和现有配置中使用完全相同的 endpoint 字符串，避免 localhost / 127.0.0.1 等别名影响失败恢复。文件内只保存连接资料，不放可执行命令、密钥或私人录音；圈说不会执行登记文件中的脚本。

登记目录独立于 settings.json，可以在圈说运行时更新，无需为登记本身退出应用。完成后让我在设置中点“刷新已接入模型”，对应卡片应显示“已登记 · 切换时验证”。除非我明确要求现在切换，否则保留当前选择。若我要求你完成切换，可在无录音时点击“验证并切换”：圈说发送半秒静音，核对 name 和 catalogId 后保存新的本地地址和配置 ID。失败保留原配置；同一网关切换失败时会再请求原模型尝试恢复。未成功核对不能宣称接通。

切换成功后，圈说自行把当前 `speechProvider` 设为 `local`，将登记的 endpoint / model 写入 `localSpeechEndpoint` / `localSpeechModel`，保留云端配置和其他设置。agent 无需为登记手动修改这些当前选择字段。

只下载权重或只写登记文件都不算完成。必须记录实际服务地址、启动方法、运行设备，并确认服务可接收圈说连接。若所选模型不在三个条目中，应先说明它需要高级地址手动接入，不能冒用这三个 ID。

## 多模型的加载与显存

圈说管理连接选择，模型的装载和释放由本地服务负责。打开设置、刷新列表和复制提示词都不会加载模型；点击切换和开始录音才建立识别连接。不要把三个模型都启动成常驻 GPU 模型来冒充自由切换。

优先提供一个常驻但不占模型显存的轻量网关，按 start.model 选择已经安装的模型，串行管理推理工作进程。不同 Python/WSL 环境可用隔离工作进程，网关负责启动、就绪、音频转发与退出。切换到另一个 GPU 模型前先回收旧模型及缓存；加载失败时可响应圈说对旧 ID 的恢复请求。不能在正在录音/转写时卸载；明确返回忙碌，不终止别的应用。

也可使用不同本机端口，但它们必须共享 GPU 排他或资源协调：加载新 GPU 模型前，确认旧 GPU 模型及缓存已经释放；仅设置空闲延迟卸载不够。圈说不会替不同端口停止旧服务，没有跨服务协调能力时应采用单一串行网关，不得宣称已支持无须手动操作的 GPU 模型切换。CPU 小模型是否常驻可按预算决定。模型缺失或预算不足时返回明确错误，不得在连接时自动下载、升级依赖或改用别的模型/云端。使用固定本地权重路径或运行时的离线模式来保证这一点。

按我的方案提供轻量服务的一次启动方法，说明重启电脑后是否要先启动服务；未经明确授权不新增开机启动。服务未启动时圈说会提示切换失败，界面不会偷偷执行安装脚本。冷启动超过 90 秒需优化启动/预热并说明取舍。

至少验证：目标模型的真实语音识别；已接入模型 A → B → A（如果只有一个，就记录另一模型切换尚未验证）；未安装 ID 拒绝；错误 ID 不回落默认模型；新模型加载失败后原配置可恢复；模型切换前后的峰值占用与旧 GPU 进程/缓存释放。不要为完成 A → B 测试擅自下载第二个模型。

界面当前模型卡片应显示实际名称、设备、精度和预算。经用户同意再验证实体麦克风与结束粘贴；无法操作的项目留为待用户确认，不把静音或模拟测试当作准确率证明。
