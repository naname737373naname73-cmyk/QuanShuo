# 录音窗口的全局空格修复 · 2026-11-06

对应本地版本 0.1.2。解决切到其他应用后，无法用空格暂停或继续录音的问题。

## 用户可见行为

- 录音窗口显示且尚未结束时，空格暂停，再按一次继续。打开后不需要先点击窗口，在其他应用前台也可使用。
- 这一期间，其他应用的普通空格会被用于控制圈说。窗口显示“全局空格暂停 / 继续”。
- 点击圈说的转写文字开始编辑时，空格用于文字输入。离开圈说文字编辑、切到其他应用后恢复全局控制。
- 长按只切换一次；用于打开录音的那次空格尚未松开时，不会立刻误暂停。
- 静音一分钟自动暂停后，仍可用空格继续。
- 开始结束录音时立即释放快捷键，不必等模型收尾完成。隐藏、关闭、销毁窗口也会释放。
- 若其他程序已经注册同一快捷键，显示“空格被占用，请点暂停/继续”，保留按钮操作，并在冲突消失后恢复。

## 实现与独立审查

旧版仅在 WinForms 窗口的 `ProcessKeyPreview` 中处理空格，无法接收到其他应用的按键。新版使用独立的 `RecordingPauseHotkey`，通过 Windows `RegisterHotKey` 临时注册普通空格，用 `MOD_NOREPEAT` 防止按住重复触发；没有增加键盘钩子。

前台窗口和文字焦点共同决定是否在编辑，避免 WinForms 保留上次文字焦点、导致切走后无法重新启用。录音协调器在异步收尾前发送带记录 ID 的停止通知，防止等待模型时仍占用空格，也防止旧通知影响下一条录音。

两名子代理分别负责独立代码审查和真实按键回归。审查提出的按键抬起、窗口句柄销毁、异步结束路径和提示刷新问题均已纳入修复。

API 依据：[Microsoft RegisterHotKey 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)。

## 验证

旧版从提交 `421d4072a9eded0ef68ad936898cd8ab2aa77e13` 导出到隔离目录，实键检查 4 项中 2 项失败：切到外部窗口后没有暂停，空格进入外部文字框。旧版首次打开无需点击在这次机器环境下通过，因此不将该现象描述为稳定复现。

修复后，68 项真实按键及生命周期检查全部通过，覆盖两种皮肤 × 纯语音窗口和截图录音卡、跨进程前台切换、长按、编辑文字、模拟输入法组字路由、隐藏与重新显示、冲突恢复、多个窗口争用和异步收尾。测试逐次校验前台属于测试程序，使用隔离文字窗口及假录音回调，不打开麦克风、真实识别服务或用户录音。

原有 64 项键盘检查与四组静音暂停检查全部通过，保留原有断言。回归期间捕获并修正了结束录音自动转入文字框时，提前丢失本地空格按下状态的问题；结束后的那次抬键仍会被消费，不会误触其他按钮。

证据位于本机 `artifacts/global-space/before.json`、`after-final.json`、`global-final.txt`、`legacy-final.txt` 和 `build-final.txt`。测试入口与运行说明见 `tests/QuanShuo.Recording.Tests/README.md`。

另外通过了 50 项本地语音接口回归、6 项核心保存回归、完整前端与原生安装包构建。交付校验逐项比较内嵌前端、程序集、提示词、许可证，以及便携版、安装包和 ZIP 中的程序字节；原位安装后再次比较 SHA-256 和随附文档。结果见同目录 `local-asr-final.log`、`core-final.log`、`delivery-final.log`、`installed-final.json`。旧安装文件备份在 `installed-0.1.1-backup`，记录和模型配置不迁移。这些记录对应发布前的本机验收；后续公开版本见项目 Releases 与更新记录。

这不是所有应用、管理员窗口、远程桌面或游戏环境的兼容性保证；输入法检查验证组字状态下不截获空格，未代替真实输入法候选选择测试。实际麦克风识别质量不属于本次快捷键修复验证范围。
