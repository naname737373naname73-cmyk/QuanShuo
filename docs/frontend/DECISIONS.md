# 前端取舍记录

## 2026-11-02：语音框是主界面的一部分

- 背景：语音框连续多轮被否。根因是一直在单独设计这个框：取色来自 `STARLAKE_BRIEF.md`，而实际渲染出来是紫色的夜；照片的山和主窗口的山是两座山。
- 选择：做子窗口时以主窗口的真实画面和用户认可过的部件为标准。语音框的玻璃参数直接取自星图日历，主按钮和“复制给 AI”相同。比稿时把稿子按真实大小贴到用户的主窗口截图上看。
- 选择：不用照片，玻璃底图是自己的湖景模糊后烘出来的（`frontend/tools/bake-voice-glass.mjs`）。代价是用户早先说过想要真实的山，这里没有山，也就不会有两座山。
- 选择：文字框不换。`LiveTextBox` 靠系统编辑框做语音插入和输入法，只让它画进一块铺好背景的缓冲。编辑框有些时候直接画屏、滚动时搬像素，所以这些消息之后整块重画，见 `DrawsDirectly`。
- 选择：大圆角用一层垫在窗口下面的透明窗口（`CardHalo`）。系统圆角只有 8 像素，`SetWindowRgn` 有锯齿，逐像素透明的窗口放不了系统控件。窗口裁小一圈，边缘露出下层抗锯齿的同一块玻璃，阴影也画在这一层。
- 代价：裁过形状的窗口不归 DWM 管边框，要拦 `WM_NCPAINT` 和 `WM_NCACTIVATE`，否则失去焦点时老式标题栏直接画在内容上。下层窗口第一次出现在高分屏时会被 `WM_DPICHANGED` 改成默认大小，要拦掉。拖动时下层可能晚一帧。
- 选择：标题走 GDI。思源宋体是可变字体，GDI+ 只取最细的字重。

## 2026-11-02：星湖只留傍晚和夜晚

- 用户决定。`scene.config.json` 里清晨和正午的配色还在，时段值仍是 0 到 3，只是界面和 `clampDay` 不再让它们出现，这样改动最小。浅色令牌同理。
- 原生窗口不看网页，自己按时钟算，规则在 `NativeTheme.IsDuskAt`，要和 `query.ts` 的 `CLOCK_KEYS` 一起改。拖过滑块时网页通过 `scene.day` 告诉原生层，主窗口关掉后作废。

## 2026-11-02：两套皮肤

- 背景：日历和录音窗口是米色花框，主窗口是星空玻璃，圈选和菜单是深蓝，同一条记录一边是星一边是花。用户要分成两种画风。
- 选择：星湖（默认）和海棠各管全部界面，花框只留在海棠。安装器还没有设置可读，一直是星湖。
- 选择：海棠不随时间变化，只用粉色那幅。代价是夜里比星湖亮，纸色因此压暗了一档。青色的圆没有用，以后要加第三套时可以用。
- 选择：画本来开满花，和“今天开了 0 朵”矛盾，所以每天从淡墨稿开始，一条记录上色一朵花。试过按月累积，和标题的“今天”对不上。
- 选择：切花靠种子位置和颜色分割（`frontend/tools/bake-crabapple.mjs`）。圆形遮罩会带出一圈深色叶子，GPT 画的遮罩对不准。换画要重新定种子。
- 选择：SVG 版海棠 11 MB，放大后边缘有像素阶梯，所以让 GPT 重画了一幅专用的方形画，要求花和花分开，切出来才干净。
- 选择：换皮肤时整页重开。两套场景的资源完全不同，3D 湖的显存这样才能释放。重开前先等文字落盘。
- 选择：海棠的标题和按钮用宋体感的字，用户说的话继续用无衬线。内容不固定，打包的字体没有全部汉字；小字号也是无衬线好读。原生窗口的按钮里有程序名，同样不用打包字体。
- 代价：原生窗口的布局按皮肤分了两套数字。海棠的控件要对准底图，星湖的文字区大一些。

## 2026-11-01：日历和录音窗口用位图底图

- 后续：2026-11-02 改成两套皮肤后，这批底图删除，见“两套皮肤”。
- 背景：用户要这两处做成新艺术风格，参考图是《第五人格》的海报。只取风格，角色、标志和文字都不用。
- 试过：让 GPT 手绘可拼接的 SVG 边框，同时用图片模型直接出整张。
- 选择：底图用图片模型生成，保存在 `src/QuanShuo.Native/Assets/Nouveau` 和 `frontend/public/assets/nouveau`。整张图的花饰更丰富，SVG 只用了日历里的四朵小花。
- 约束：文字框是纯色的，所以生成后把底图里的奶油色区域填平成 `#F7EFDC`，和 `NativeTheme.Cream` 一致。重新生成底图时要同样处理，否则文字框周围会看到色块。
- 悬浮窗能改大小，它的底图只在四角有花，四边是直线，按九宫格拉伸不变形。录音卡片尺寸固定，用整张缩放。
- 底图只按窗口尺寸缩放一次并缓存。音量动画每秒重绘 30 次，每次都高质量缩放会卡。
- 窗口不再用系统圆角，圆角会切掉四角的花饰。

## 2026-11-01：语音优先直连，不跟系统代理

- 背景：`ClientWebSocket` 和 `HttpClient` 默认走系统代理。这台机器的代理是 `127.0.0.1:7897`，阿里云又在国内，语音等于绕了一圈。
- 实测（同一段合成语音，按说话速度发送）：8 秒语音直连 10 秒、最长卡顿 1.7 秒；走代理 30 秒、最长卡顿 6 到 12 秒。换 4 个模型结果一样，所以不是模型的问题。一分钟的语音走代理 2 次都失败，直连完整。
- 选择：先直连，握手 5 秒内没成功再走系统代理。不加设置项，用户不需要知道这件事。
- 放弃：完全不走代理。公司网络可能只能通过代理出去，那时慢一点也比连不上好。
- 代价：退回代理时仍然可能被服务端断开，这种情况下文字和 WAV 保留，可以重新转写。

## 2026-11-01：边说边改

- 背景：识别服务每次返回从头到现在的全文，最后一句还会被修订，而用户随时可能改任何位置。
- 试过的思路：把全文和用户文字做三方合并。放弃原因：一句话被修订时前后差异很大，合并结果不可预测。
- 选择：`LiveTranscript` 只记住“正在修订的那一段”在文档里的位置。改了别处，这段平移；改到这段本身，到此为止的文字归用户，之后只追加新说的部分。一句说完后下一句写到光标处，和输入法语音输入一致。
- 定位不到时宁可重复一两个字，也不能吞掉新说的话。
- 合并和用户修改都在 UI 线程，不需要处理交错。识别结果投递到 UI 线程后按顺序执行，所以 `FinishAsync` 等到 task-finished 时结果都已合并。
- 输入法组字和鼠标拖选时不改文字，否则候选词和选区会被打断。识别结果是全文，只留最新一次，结束后补上。
- 原生 `TextBox` 而不是 WebView2：悬浮窗要按下快捷键就开始听，WebView2 启动要一秒以上。代价是录音中 Ctrl+Z 基本无效：每次写入识别结果都会清空系统编辑框的撤销记录。暂停或结束后可以撤销。

## 2026-11-01：说话悬浮窗

- 文字贴回去用剪贴板加 Ctrl+V，不逐字模拟按键：中文输入法开着时逐字发送会被输入法吃掉。代价是剪贴板内容被替换。这也是兜底，目标窗口拒收时用户还能手动粘贴。
- 目标窗口是最后一个非圈说的前台窗口，每 300ms 跟一次，所以窗口开着时点到别的程序就贴到那里。
- 目标是管理员权限的程序时，系统会静默拦截按键，无法检测到失败，文字仍在剪贴板里。
- 什么都没说的记录直接删除，不进回收站：用户没有产生任何内容。识别失败的记录保留，录音还能重新转写。
- 快捷键选 Ctrl+Alt+H：和圈选的 G 相邻，H 取“话”。Ctrl+Alt+V 在 Office 里是选择性粘贴，Ctrl+Alt+S 是 QQ 的旧快捷键。

## 2026-11-01：语音模型换代

- 默认模型改为 `qwen-audio-3.1-asr-flash-message`。官方定位是输入法和语音消息，首字延迟低，和圈说的用法一致。
- 三类模型协议不同，不能只换名字。由 `SpeechModels.KindOf` 分流：
  - 流式：`wss://.../api-ws/v1/inference` 的 `run-task` 协议。Qwen-Audio 模型要开 `intermediate_result_enabled`，否则只在句末返回结果。中间结果按 `sentence_id` 覆盖，不能拼接。
  - 整段：`https://.../api/v1/services/aigc/multimodal-generation/generation`，音频用 `data:audio/wav;base64,` 放在 `input_audio.data`。单次 5 分钟。
  - 只收 URL：`*-filetrans` 要公网地址。本地录音上传到第三方存储不符合“记录留在本机”，所以不接入，下拉框列出但禁用。
- 删除下拉项 `qwen3-asr-flash-realtime`：它在 `/inference` 上返回 `ModelNotFound`，要用另一套 `/realtime` 协议。已保存的值在读取设置时换成默认模型。
- 域名：本账号实测 `dashscope.aliyuncs.com` 对流式和整段接口都可用，不要求填 Workspace ID。整段接口的域名从识别地址推导。
- 超过 5 分钟的录音改走流式，不按说话速度发送。376 秒音频 19 秒转完，文字完整。
- 暂停时发静音：服务端约 20 秒没收到音频就断开，实测暂停 30 秒必断。静音不写入 WAV。
- 没听到人声不算失败：整段接口返回 `ASR_RESPONSE_HAVE_NO_WORDS`，按空文字处理。短于 0.3 秒的音频不发请求，否则服务端既不返回也不报错，请求一直挂着。
- 超时必须抛 `TimeoutException`。`TaskCanceledException` 属于取消，`RecordingCoordinator` 的失败分支不接，录音流程会停在半路。

## 2026-11-01：Paraformer 实时协议与本地恢复

- 官方模型：`paraformer-realtime-v2`，华北2（北京），模型原价 `0.00024 元/秒`；来源为阿里云模型信息页 `https://help.aliyun.com/zh/model-studio/paraformer-realtime-v2`。
- 协议：`wss` 连接后发送 `run-task`，等待 `task-started`，再发二进制 PCM，结束发送 `finish-task` 并等待 `task-finished`。客户端事件参考 `https://help.aliyun.com/en/model-studio/paraformer-client-events`，服务端事件参考 `https://help.aliyun.com/en/model-studio/paraformer-server-events`。
- 音频：16kHz、16bit、单声道 PCM；开启标点、ITN、心跳，不做 AI 改写，不用静音作为结束条件。
- 域名：官方推荐业务空间专属域名 `{WorkspaceId}.cn-beijing.maas.aliyuncs.com`，同时明确现有 `dashscope.aliyuncs.com` 仍可使用。只有 API Key 的默认配置保留后者，有业务空间时可在高级设置改地址。
- 失败策略：网络或 Key 错误只停止发送，本地录音继续；WAV 头持续更新，已有转写持续原子落盘。
- 本地验证：3 个麦克风设备；无 Key 录音约 0.6 秒后状态为 `Incomplete`，WAV 保留，16044 字节文件中 PCM 数据为 16000 字节，与 WAV 头一致。
- DPAPI 验证：隔离密钥文件的加解密一致，密文搜不到测试用的假 Key；未读取或覆盖用户真实 Key。

## 2026-11-01：历史界面的两轮设计审查

- 第一轮颜色：嫩叶绿负责结构与状态，花瓣粉只用于主按钮、选中和花；水面、浮尘、花蕊各有独立 token，夜晚用墨绿而非纯黑反色。
- 第一轮字体：Display 用于今日数量与视图标题，Text 用于正文，Cascadia Mono 用于时间和路径；选择 Windows 原生字体是需求约束，不是缺少字体决策。
- 布局比较：右侧卡片流和三栏仪表盘会让“找记录、复制、看树”同时争夺注意力；因此只保留左侧采集匣，详情和设置也在其中切换。
- 第二轮自我审查：左侧栏本身可套用到任何工具，不能作为招牌；独特性只能来自“记录 ID 与花朵 ID 的真实绑定”。其他装饰必须让位。
- 删除项：右下角落装饰文案被移除，因为文字不应直接压在动态画面上；顶部重复日期被合并为滚动后的吸顶日期。
- 当前不确定：SVG 树冠太规则、光束过亮、最终插画的治愈感是否足够，这些需要用户生成素材后由精修者判断，不在文档里自称“已达到最终效果”。

## 2026-11-01：长按右键降级为可选开关，快捷键为默认触发

- 背景：实机验收当天出现两个"杀不死"的进程（线程卡死在内核层，TerminateProcess 无效），均与全局鼠标钩子链路相关；用户确认产品定位是"工具"而非常驻系统底层的隐形产品。
- 决定：`rightClickCaptureEnabled` 默认 `false`——默认配置下不安装 WH_MOUSE_LL 钩子、不拦截任何鼠标事件，唯一触发方式是快捷键；钩子只在用户显式开启后加载，关闭开关即时卸载。
- 放弃的方案：钩子健康自检（检测自身超时并自动重装钩子）——治标，且用户已明确不需要常驻拦截。
- 同日修复：钩子 Dispose 超时不再抛异常（避免退出流程被卡死）；开发构建（bin 目录）不再注册开机自启（测试实例曾把 Debug 版写进 Run 项，重启后自动运行）。

## 2026-11-01：彻底移除长按右键，改为快捷键唯一触发（用户指令）

- 背景：需求变更，工具定位。此前一天内出现两个"杀不死"的进程，均与 WH_MOUSE_LL 全局钩子链路相关；用户决定任务书中所有右键长按内容作废，不保留开关。
- 决定：删除 MouseHookService 与全部引用，全项目不再出现 SetWindowsHookEx / WH_MOUSE_LL。选区只由快捷键触发，覆盖层用左键拖选。
- 卡死根因分析（两次幽灵进程）：钩子回调内在低级钩子上下文里调用 SendInput 重放右键，输入管线在处理原始事件期间需重入，线程可能永久阻塞在 win32k 内核等待；TerminateProcess 无法结束卡在内核等待的线程，进程进入"终止挂起"状态。死钩子留在链条里还会给每个鼠标事件增加系统超时延迟（用户感到"鼠标卡"）。移除钩子后此类问题在架构上不再可能发生。
- 单实例严格化：删除 QUANSHUO_INSTANCE 绕过（测试专用后门不再保留）；第二次启动通过 Local\QuanShuo.Activate 事件通知已运行实例打开历史窗口后自行退出。旧实例卡死时不允许另开实例绕过，必须先结束旧进程并查明原因。
- 默认快捷键 Ctrl+Alt+A → Ctrl+Alt+G：避开 QQ 默认截图键。快捷键注册失败时气泡提示并直接打开设置页当场修改。
